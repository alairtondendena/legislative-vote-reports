# Legislative Vote Reports

A small command-line tool that reads US congressional voting data from CSV files and reports how each legislator voted and how each bill was voted on.

**Where to start.** The counting logic is in [`vote_reports/reports.py`](vote_reports/reports.py), about 160 lines with no file I/O. [`csv_io.py`](vote_reports/csv_io.py) reads and validates the input, and [`cli.py`](vote_reports/cli.py) connects the two. Everything else is evidence: the tests show the reports are correct, and the benchmark shows how time and memory scale. The questions behind the design (complexity and trade-offs, adding columns, reporting on a given list of legislators or bills, development time) are answered in [docs/DESIGN.md](docs/DESIGN.md), §1-§4.

## Input

Four CSV files, in `data/` by default:

| File | Columns | Meaning |
|---|---|---|
| `legislators.csv` | `id, name` | A legislator |
| `bills.csv` | `id, title, sponsor_id` | A bill and the legislator id of its primary sponsor |
| `votes.csv` | `id, bill_id` | A vote held on a bill (at most one per bill) |
| `vote_results.csv` | `id, legislator_id, vote_id, vote_type` | How one legislator voted in one vote: `1` = yea (support), `2` = nay (oppose) |

The sample data in `data/` covers two 2021 House votes: 19 representatives voting on the Build Back Better Act and the Infrastructure Investment and Jobs Act.

## Output

| Report | One row per | Columns |
|---|---|---|
| [`output/legislators-support-oppose-count.csv`](output/legislators-support-oppose-count.csv) | legislator | `id, name, num_supported_bills, num_opposed_bills` |
| [`output/bills.csv`](output/bills.csv) | bill | `id, title, supporter_count, opposer_count, primary_sponsor` |

A legislator *supports* a bill by voting yea on it and *opposes* it by voting nay. `primary_sponsor` is the sponsor's name, or `Unknown` when the sponsor is not in `legislators.csv`. Every legislator and every bill gets a row, even with no votes. The reports for the sample data are committed, so you can read the results without running anything.

## Running it

**With Python 3.10 or newer.** The program uses only the standard library, so there is nothing to install:

```bash
python3 -m vote_reports
```

This reads `data/` and writes `output/`. Other folders: `python3 -m vote_reports --data-dir DIR --out-dir DIR`.

**With Docker** (no local Python needed):

```bash
docker compose run --rm reports   # writes ./output from ./data
docker compose run --rm check     # lint (ruff), type check (mypy --strict) and all tests
```

## Running the tests locally

Development tools are managed with [uv](https://docs.astral.sh/uv/):

```bash
uv sync                                   # installs pytest, ruff and mypy into .venv
uv run pytest                             # all tests
uv run pytest tests/test_reports.py       # one file
uv run ruff check . && uv run mypy        # lint and type check
uv run python -m scripts.benchmark        # time and memory scaling (Linux; a few minutes)
```

## Results on the sample data

| Bill | Supporters | Opposers | Primary sponsor |
|---|---:|---:|---|
| H.R. 5376: Build Back Better Act | 6 | 13 | Rep. John Yarmuth (D-KY-3) |
| H.R. 3684: Infrastructure Investment and Jobs Act | 13 | 6 | Unknown |

Each of the 19 legislators who voted supported one bill and opposed the other. Rep. John Yarmuth cast no votes in the data and is reported with 0 and 0. H.R. 3684's sponsor (id `400100`) is not in `legislators.csv`, so it is reported as `Unknown`.

## How correctness is shown

The tests (`tests/`) check the results in four independent ways:

1. **Hand-written expected reports.** [`tests/expected/`](tests/expected/) was written by hand from the input CSVs, cross-checked with `awk`, and never generated by the code. The program's output must match it exactly.
2. **A second implementation in SQL.** Both reports are recomputed in SQLite with `LEFT JOIN`s and `GROUP BY`, and compared row by row. This runs on the sample data and on six seeded random datasets, three of which contain every kind of bad reference listed below.
3. **Totals that must agree.** On clean data, the per-legislator totals and the per-bill totals each add up to the number of vote results.
4. **One unit test per edge case**, plus tests for CSV parsing and the command line.

To check that the tests catch real mistakes, bugs were injected into the code on purpose (yea/nay swapped, empty sponsor, rows sorted by id, and others). The test suite failed for every one.

## Data handling

| Situation | Behaviour |
|---|---|
| Sponsor blank, or not in `legislators.csv` | `primary_sponsor` is `Unknown` |
| Legislator or bill with no votes | Included, with zero counts |
| Vote result for an unknown legislator | Counted in the bill's totals; no legislator row; warning |
| Vote on a bill missing from `bills.csv` | Counted in the legislator's totals; warning |
| Vote result for an unknown vote | Skipped (it can't be linked to a bill); warning |
| `vote_type` other than 1 (yea) or 2 (nay) | Skipped; warning |
| Empty file, missing column, or a row with too many or too few fields (e.g. an unquoted comma) | Stops with an error naming the file (and line) |
| Non-integer id or vote type | Stops with an error naming the file and line |
| The same id twice in `legislators.csv`, `bills.csv` or `votes.csv` | Stops with an error naming the file, line and id |
| Extra columns | Ignored |
| Row order | Same as the input files |
| CRLF or LF line endings, UTF-8 with or without BOM, quoted fields | All accepted |

In short: a file that contradicts itself stops the run; a reference to something missing elsewhere only warns. A failed run never replaces earlier reports. Warnings go to stderr; the sample data produces none. Two things are not checked, because checking them would cost memory proportional to the number of vote results: that each legislator votes at most once per vote, and that vote result ids are unique; see [the design notes](docs/DESIGN.md#trade-offs).

## Performance

Time grows linearly with the input: 260,000-340,000 vote results per second at every size measured, and 8.7 million rows in 27 s. Memory does not grow with the number of vote results: about 17 MB peak whether there are 0.5 or 8 million of them. Both are measured by [`scripts/benchmark.py`](scripts/benchmark.py); see [the design notes](docs/DESIGN.md#1-time-complexity-and-trade-offs).

## Project layout

```
vote_reports/   the program: models.py (records), csv_io.py (reading/writing),
                reports.py (counting, no I/O), cli.py (command line)
tests/          unit, end-to-end and SQL cross-check tests; expected/ holds hand-written reports
scripts/        synthetic.py (random test datasets) and benchmark.py
data/           the sample input CSVs, unchanged
output/         the generated reports
docs/           DESIGN.md, DECISIONS.md, AI_USAGE.md
```
