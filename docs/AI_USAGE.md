# AI Usage

This project was built with AI assistance. This document records how it was used, what the author decided, and how AI-produced work was checked.

## Tooling

- **Claude Code** (model: Claude Opus 5.5), used in VS Code as a pair-programming agent.
- **`CLAUDE.md`** (repo root): the context file Claude Code reads at the start of each session. It holds the requirements, data model, known data gotchas and expected results. It was generated with `/init`, reviewed by the author, and is kept in the repo on purpose as part of the workflow.

## Principles

1. **The author decides; the AI proposes.** Design choices are made by the author and recorded with their reasons in [DECISIONS.md](DECISIONS.md).
2. **AI output is not trusted without checking.** Every claim about results is backed by tests, or by values the author re-derived by hand (see [DECISIONS.md §4](DECISIONS.md#4-verification)).
3. **Separate checks.** The SQL cross-check test is a second implementation of the same reports. It exists to catch mistakes in the main code, whether they came from a person or a model.
4. **No code the author can't explain.** Everything committed has been read and understood by the author.

## Session log

Each session lists what Claude did, including the mistakes it caught in its own work, and what the author decided or checked.

### 2026-11-17: Setup

- **Claude:** read the requirements and the CSVs and generated `CLAUDE.md`, including the data gotchas (the `sponsor_id` header is called "Primary Sponsor" in the requirements; the `bills.csv` report name collides with an input file; sponsor `400100` is unknown; Yarmuth cast no votes) and the expected counts.
- **Author:** reviewed `CLAUDE.md`.

### 2026-11-17: Planning

- **Claude:** drafted a plan. Proposed the standard library instead of pandas. Pointed out that the memory target rules out detecting duplicate votes, which would need O(R) memory.
- **Author:** chose the standard library, set the streaming time and memory target, asked for Docker Compose so others can run it easily, and asked for AI use to be documented.

### 2026-11-17: Core implementation

- **Claude:** set up the repo and tooling and wrote the streaming pipeline, the first tests and the Docker setup. While checking the expected values with `awk`, found that `bills.csv` and `votes.csv` use CRLF line endings, which had produced a false "missing sponsor" result. Caught two mistakes in its own manual test setup before drawing conclusions from them.
- **Author:** the expected reports in `tests/expected/` were written by hand from the CSVs and checked with `awk`, not generated by the code.

### 2026-11-17: Tests, cross-check, benchmark, docs

- **Claude:** wrote the edge-case tests, the SQL cross-check, the synthetic data generator, the benchmark, the README and the design notes. Caught and fixed four of its own mistakes:
  - The first benchmark measured child memory with `wait4`, which on Linux includes the parent's memory, so the early numbers were inflated. Confirmed with a 300 MB test before fixing it.
  - The first synthetic generator wrote rows in id order, so a sort-by-id bug passed every synthetic case. Found by injecting that bug on purpose.
  - Removed unnecessary code from its first draft of the generator.
  - Removed claims from the docs that went beyond the evidence ("several times faster", "byte for byte").
- **Author:** bugs were injected on purpose to confirm the tests catch them; all 6 were caught. Performance claims are backed by the benchmark and a profile.

### 2026-11-17: Preparing for publication

- **Claude:** renamed the package to `vote_reports`, reorganized the docs into DESIGN.md and DECISIONS.md, described the input format in the README, and measured development time from the session transcripts.
- **Author:** chose the package name, and decided that development time means time spent in the Claude Code sessions.

### 2026-11-17: Audit of assumptions and validation

- **Claude:** listed the assumptions and tested suspected gaps against the real program. Found four kinds of input that produced wrong reports with exit code 0:
  - an unquoted comma in a title;
  - a repeated vote id, which moved one bill's votes to another, with a misleading warning;
  - repeated legislator or bill ids;
  - an empty or header-only file.

  Also found that a failed run overwrote earlier reports. Three of its first probe runs were invalid, because rows were appended to files without a final newline; it noticed from the garbled output and reran them. Then added header and field-count checks, repeated-id checks and staged writes, with a test for each, and disabled each check once to confirm a test fails.
- **Author:** accepted O(L+B+V) memory so repeated bill ids can be rejected, and agreed the rule: a file that contradicts itself stops the run; a broken reference only warns.

### 2026-11-18: Review and publication

- **Claude:** did a full code review of the project as a newcomer would read it. Found that `Tally.add` counted any vote type other than yea as opposition, so adding a type such as "Present" later would silently count those votes as nays. Fixed it so only explicitly mapped types are counted, and added a test that fails if the old behaviour returns. Added a "Where to start" note to the README and rewrote this log as bullet points.
- **Author:** reviewed the code and the results line by line, including the hand-written expected reports, and confirmed they are correct. Approved publishing the repository.

Development time per phase, measured from the session transcripts, is in [WRITEUP.md §4](../WRITEUP.md#4-how-long-did-the-work-take).
